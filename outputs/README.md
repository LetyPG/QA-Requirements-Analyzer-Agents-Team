# Final Analysis Outputs & Deliverables

This directory is a dedicated to store **User Deliverables and Business Artifacts**, upon successful completion of a requirement analysis workflow. It stores the primary results generated by the sub-agents and consolidated by the **`orchestrator-agent`** for user consumption  and downstream automation purposes and system integrations.

---

## Directory Structure

When a requirement (e.g., `RF-CAT-01`) is analyzed and passes Quality Gate validation, a dedicated timestamped folder is created here:

```text
outputs/
└── {RF_ID}_{timestamp}/
    ├── final_report_{RF_ID}.md     # Human-readable Markdown report
    ├── final_report_{RF_ID}.json   # Programmatic JSON report payload
    └── strategy_{RF_ID}.json       # Risk & QA strategy payload
```

---

## File Overview

| File | Format | Description |
| :--- | :--- | :--- |
| `final_report_{RF_ID}.md` | Markdown | Consolidated analysis report including Acceptance Criteria (Gherkin), Non-Functional Requirements (NFRs), Risk Matrix, and recommended QA Strategy. |
| `final_report_{RF_ID}.json` | JSON | Machine-readable report payload containing full traceability metrics and workflow resource usage stats. It is setup in case of external integrations with document or ticketing platforms through APIs or MCP servers |
| `strategy_{RF_ID}.json` | JSON | Standalone risk evaluation and test strategy specification payload. |

---

## Guidance for Users

- **Automatic Generation:** Files in this directory are generated automatically by the Orchestrator Agent upon successful validation.
- **Usage:** Use `.md` files for human review and documentation, and `.json` files for downstream automated testing tool integrations.
- **Clean up:** These outputs can be archived or safely removed if no longer required.
